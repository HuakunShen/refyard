# The SSH fixture server

A container running a real `sshd` and a real `git` on an Alpine base — and nothing else.
It is what makes "the reads work over SSH with nothing installed on the remote host" a
measurement instead of a claim, and it is what
`crates/refyard-host/tests/ssh_exec.rs` talks to.

- `Dockerfile` — the server image (`openssh` + `git` from Alpine; no Refyard artifact, no
  Node/Bun/Deno, no language runtime of any kind).
- `sshd_config` — public-key only, no forwarding, no tunnels, `gituser` only.
- `scripts/native-ssh-fixture.ts` — everything on the client side: builds the image,
  generates the host key and the client key **locally**, writes the client's
  `known_hosts` from the public key it just generated, seeds the repository, and reports
  where things are.

## Running it

```sh
pnpm native:ssh:fixture -- start     # build, run, seed, write target/native-ssh-fixture/state.json
pnpm native:ssh:fixture -- status    # what is running, and the state file
pnpm native:ssh:fixture -- stop      # remove the container and its network
```

Then, while it is up:

```sh
cargo test -p refyard-host --test ssh_exec -- --ignored --test-threads=1
```

`start` is safe to run twice: it removes and recreates its own container, keeps the keys it
already generated, and rewrites the scratch home and `state.json`. `stop` is safe to run
when nothing is running.

## What it does and does not touch

- **Never `ssh-keyscan`.** The host key is generated by the script on this machine, and the
  client's `known_hosts` is built from that public key before the container is even asked
  for one. Blind trust is the failure this fixture exists to make impossible.
- **Never the developer's `~/.ssh`.** The client is pointed at the fixture's own
  configuration with `-F`, and that file names an absolute `IdentityFile` and
  `UserKnownHostsFile` inside `target/native-ssh-fixture/`.
  `HOME` alone would not have been enough: OpenSSH resolves `~/.ssh/config`,
  `~/.ssh/known_hosts` and `~` inside option values from the **passwd entry for the uid**,
  not from `HOME`, so a scratch `HOME` silently reads the real user's files. That was
  measured on macOS (OpenSSH 10.3) and on this image's Alpine `ssh` (9.7) before the
  fixture was written this way.
- **A private network and an ephemeral port.** The container joins its own user-defined
  network and its port is published on `127.0.0.1` only, with the host side chosen by
  Docker. (A Docker `--internal` network cannot publish a port at all, so the network is
  private by name and membership rather than by egress denial.)
- **No global SSH or Git configuration is modified.** The container's own repository config
  is written inside the fixture repository, and nothing is written outside
  `target/native-ssh-fixture/` on this machine.

## The state it stages

`state.json` in `target/native-ssh-fixture/` names everything a test needs: the alias, the
client configuration file, the remote repository path, and a byte-for-byte copy of that
repository on this machine. The tests run every read plan over SSH **and** over that local
copy, then compare the raw stdout — a difference is then a difference the transport made.

The repository path is deliberately hostile to quoting: `/srv/refyard fixture's rëpo`
contains spaces, an apostrophe and a non-ASCII character. A tracked file named
`weird 'quoted' name.txt` is modified in the worktree, and an `untracked file.txt` exists,
so status and diff both carry paths an unquoted command string would mangle. The tree also
holds a binary file with NUL bytes and a non-ASCII name with no canonical decomposition, so
a name this host's filesystem might normalise is never part of a byte comparison.

## What is _not_ verified by this fixture

- The container has outbound network reachability through Docker's NAT (only the published
  port is used by the tests); nothing in it downloads or installs anything at run time.
- While `-F` skips the system-wide _configuration_ file, the client still consults
  `/etc/ssh/ssh_known_hosts` (the fixture's `UserKnownHostsFile` is absolute, so the
  per-user file is the fixture's own). A machine-wide entry for the same loopback address
  would still be seen; no such entry exists on the machines this was run on.
- Windows hosts and non-POSIX remote login shells are out of scope. The quoting layer
  assumes a POSIX login shell, and the provider runs its own shell probe before sending a
  read, so a shell that would mangle a command string is reported as unavailable rather
  than used.
