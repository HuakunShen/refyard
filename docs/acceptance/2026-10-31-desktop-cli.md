## What is still open

The app and the command are installed on this machine (bundle 0.3.1 in `/Applications`,
`~/.local/bin/refyard` → its launcher), and both launches were exercised. Two things could not
be observed, because Cua driver authorization was suspended (`revoke-all`) during the round:

1. the Settings → **Command line** button itself, and the message it renders (the link exists
   and works; it was created with the same target that button writes);
2. a picture of the opened tab or of a refusal banner — the tab is evidenced by the app's own
   persisted session instead of a screenshot.

Pressing the button now is still a useful check, and it is a no-op on an existing link:
Settings → Command line → **Install `refyard` command** should answer
`` `refyard` is installed at /Users/hk/.local/bin/refyard; open a directory with `refyard .` ``.
`refyard ./typo` should show a banner quoting `./typo`.

## Defects found and fixed

- `std::env::current_exe()` on macOS reports the `~/.local/bin/refyard` symlink, not the binary
  inside the bundle, so the launcher searched for the app beside the link and reported
  "no Refyard application beside this command" for every PATH install. The launcher now
  canonicalises its own path first; the regression test uses a real symlink layout.
- `ExternalBin` naming: the sidecar is `refyard-launcher` because macOS volumes are
  case-insensitive and `Refyard`/`refyard` in one `Contents/MacOS` are the same file. The first
  attempt named it `refyard` and the app and command collided.

## Unverified platforms

Windows, Linux (any architecture), and every non-macOS-arm64 bundle. `node`-side suites and the
Rust suites were run only on macOS arm64.
