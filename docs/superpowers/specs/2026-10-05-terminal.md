# Spec — integrated terminal (2026-10-05)

The user directed this repository to ship an **integrated terminal**: an occasional,
temporary shell beside the workbench, in the browser form and the Tauri desktop app.
GPUI is explicitly secondary ("if it's easy"); it is **not** implemented here — see the
assessment at the end.

## Architecture

One transport-neutral interface, two hosts, one panel:

```
TerminalPanel (packages/git-ui, xterm.js lazily imported)
      │  TerminalService (packages/git-service — one method: open)
      ├─ HTTP: packages/git-client + backend-http → Node service (packages/host-node)
      │        PTY via node-pty, optional dynamic import
      └─ Tauri: packages/backend-tauri → apps/desktop (Rust)
               PTY via crates/refyard-pty (portable-pty)
```

- **The renderer never names a path, a shell or an argument.** It names an approved
  repository id and a grid size. The Node host resolves the directory from the
  repository registry; the Tauri host resolves it through
  `ApplicationService::repository_record`. The shell is the machine's own login shell
  (Node: `$SHELL` then platform fallbacks; Rust: the passwd entry first — a GUI process
  on macOS often has no `$SHELL` — then `$SHELL`, then a default).
- **One browser session owns one terminal.** Every input/resize/close/output re-checks
  that the asking bearer session (HTTP) or window session (Tauri) is the one that opened
  the shell. A second tab cannot drive somebody else's shell even with the session id.
- **Frames are contract frames.** `TerminalOutputFrame` / `TerminalExitFrame`
  (`packages/git-contract/src/terminal.ts`), base64 in both transports; output is cut to
  32 KiB raw pieces so base64 stays under the 64 KiB payload bound.
- **Capability honesty.** `capabilities.terminal: {shell}` appears only when the host
  really has a pty; the HTTP session carries `terminal` only when the service
  advertised one; the Tauri session always does (the host always links the pty crate).
  `session.terminal !== undefined` is the single gate the UI needs.

## Transport notes

- HTTP: `POST /api/v1/terminal/{open,input,resize,close}` (scope `repository:write`)
  and one SSE stream `GET /api/v1/terminal/output?sessionId=…`. No replay and no
  reconnect: bytes a dropped connection never delivered are gone, and the observer
  hears an error instead of a silent gap. While no stream is attached the host keeps
  the newest 256 KiB, so opening the panel never shows a torn start.
- Tauri: `refyard_terminal_{open,write,resize,close}` commands plus base64 frames on
  the `refyard://terminal` event. A window that disconnects takes its shells with it.

## Dependencies and size

- Frontend: `@xterm/xterm` + `@xterm/addon-fit`, **lazily imported** — the library is
  its own chunk (≈287 KB raw / ≈67 KB gzip) downloaded only when a terminal first
  opens; the workbench's main chunk grows by ≈15 KB raw for the panel components.
- Node host: the pty comes from a **provider chain**: `@kunkun.sh/pty` (the owner's
  own ~590 KB per-platform napi binding around portable-pty, from the kkterminal
  workspace) is preferred when it resolves; node-pty is the fallback and wins on
  Windows until the small binding's ConPTY specifics are done. Both are optional
  dynamic imports (`external` in both bundle scripts); a machine with neither
  answers "no terminal" honestly. To enable the small binding locally, link it:
  `mkdir -p node_modules/@kunkun.sh && ln -snf ../../../kkterminal/packages/pty
  node_modules/@kunkun.sh/pty`. Swapping in per-platform npm prebuilds when
  `@kunkun.sh/pty` is published needs no code change. Known upstream bug in the
  fallback path: node-pty 1.1.0 ships its macOS `spawn-helper` without the
  executable bit, failing every spawn with `posix_spawnp`; the port restores the
  bit best-effort next to the loaded prebuild.
- Tauri: `portable-pty 0.9` in the new headless crate `crates/refyard-pty`, linked only
  by the desktop shell.

## GPUI assessment (not implemented)

`gpui-kit 0.7` ships no terminal widget, so a GPUI terminal means porting a VT
emulator and a grid renderer onto the gpui-pre snapshot — Zed-sized work, not a task.
The GPUI shell is the experimental front-end; the Tauri app is the desktop product.
Deferred without a date.

## Verification

- `tests/contract/terminal.test.ts` — frames, bounds, capability optionality.
- `tests/node/terminal-service.test.ts` — service rules against a fake pty
  (ownership, caps, bounded buffer, exit-once).
- `tests/integration/terminal.test.ts` — real pty over real HTTP: auth, 501 without a
  pty module, ownership across bearer sessions, echo → output frame → exit code.
- `crates/refyard-pty` tests + `apps/desktop/src-tauri/tests/terminal.rs` — real shell
  spawn, ownership across window sessions, exit code preservation.
- Not verified by automation: the panel's on-screen behaviour (no UI click automation
  on this machine — screenshot pass only), Windows, Linux.
