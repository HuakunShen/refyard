## Why this round exists

Two things are unfinished, and both are visible from outside the code:

1. **`GET /api/v1/capabilities` still names two mutations as not implemented** — `initRepository`
   and `cloneRepository`, the half of T09 that was deferred. The contract schemas, the workspace
   target and the semantic validation already exist; no planner, no effect, no panel, no test
   drives them. Until they exist, "create a repository" and "clone a repository" are the only
   entries on the product's own operation list that a user cannot perform.
2. **There is no diff-scale measurement anywhere.** `docs/evidence/performance.json` covers cold
   start, status throughput, history first page and RSS against one 100,000-commit repository. The
   decision recorded on 2026-09-15 (where command construction and parsing live) can only be
   reopened by a measurement that names a shape the current bound cannot serve — and no such number
   exists today, so the decision stands on reasoning rather than on evidence.

## Acceptance

This goal is met when, on one revision, all of the following are true and demonstrated by commands
that were actually run:

- `initRepository` creates a repository at a workspace destination inside an approved root, and
  `cloneRepository` clones an approved remote into one — both through the real surface a user has
  (HTTP + the UI), not only through an in-process call.
- `capabilities.unavailable` is **empty**, and a case asserts the set arithmetic that makes it so:
  every contract mutation is either implemented or named as missing, never both and never neither.
  `check:contract` still reports the schema gap for the two new effects as zero.
- The refusals hold, each with its own case: a destination that leaves the approved root, a
  destination naming `.git`, a remote URL that is a transport helper, and a destination that is not
  empty. A failed clone registers nothing and deletes nothing the user put there.
- `docs/evidence/performance.json` carries diff-scale measurements — at minimum: one large file,
  one very long single line, many small changed files, and a repeated repository switch — each with
  its `processScope`, `memoryMetric`, payload bytes and its observed range over repeated runs.
- `tests/pack/evidence.test.ts` still passes against the regenerated report, and
  `docs/evidence/release-matrix.md` names the two new mutations as verified, with anything not
  exercised named as unverified.

## Standing constraints

`AGENTS.md` §1–§2 apply unchanged. Specific to this round:

- Every test that writes Git state uses a temporary repository from `tests/support/repo.ts`, and
  cloning is tested against a **local bare remote** — no network, no credential helper, nothing
  that reaches outside the machine.
- No `--no-verify`, no disabled host verification, no rewritten global config, no forced operation:
  a clone that needs credentials fails with Git's own diagnostic, and that is the intended
  behaviour, not a bug to work around.
- A failed or partially completed clone is reported as such — `unknown` where the outcome cannot be
  verified — and never cleaned up recursively over a path the user chose.
- The diff measurements are policy-free: they record what was measured, on which runtime and at
  which scale, and they are the only admissible trigger for reopening the parsing-placement
  decision.
- Nothing in this round is announced before it exists: `capabilities` reports an operation exactly
  when its effect is registered.
