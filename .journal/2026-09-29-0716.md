# Timestamp: 2026-09-29 07:16 SGT

## Core decision/topic

Correct Windows private-state file creation after hosted CI showed that files
created by an elevated process may default to a group owner. Since an object's
owner implicitly receives `WRITE_DAC`, accepting that group would broaden who
can alter private-state access controls.

## Options considered

- Accept the process token's default owner in addition to `TokenUser`. Rejected:
  the default may be a group, and Windows implicitly grants an object's owner
  `WRITE_DAC`, which could let that group rewrite the private DACL.
- Create first, then change the owner and DACL. Rejected: the file would briefly
  exist under the group default owner before repair, and a temp file could
  receive journal bytes before its ACL was fixed.
- Rewrite the ownership of an existing file. Rejected: startup must not take
  ownership of existing authority files, including files with unexpected
  owners.
- Accept any owner while the parent directory is private. Rejected: that would
  trust state files that could have been planted before directory repair.
- Supply the token user's owner SID and protected user/SYSTEM DACL in
  `SECURITY_ATTRIBUTES` to `CREATE_NEW`. Chosen: new files are private from the
  instant of creation; existing authority files remain subject to strict
  current-user ownership checks.

## Final decision and rationale

Use an explicit absolute security descriptor during `CREATE_NEW`: set owner
to the token user, set the exact two-ACE user/SYSTEM
DACL, and mark it protected before the object is created. Lock files and
write-atomic temp files now use this path. Existing files are still opened
without delete sharing, checked for ordinary-file type and current-user owner,
then have only their DACL repaired through the same handle. Their owner is
never rewritten.

## Key changes made

- Added a Windows embed regression that opens and reopens a journal and verifies
  a newly created lock is owned by the token user with the exact private ACL.
- Routed journal and workspace-root temp-file creation through the explicit
  Windows private-file creator; Unix temp-file creation remains unchanged.
- Kept existing-file validation strict: unexpected owners still fail closed;
  ordinary files with the current user's owner can have DACL drift repaired.
