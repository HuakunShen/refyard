# 2026-09-29 18:22 +08 — Let stacked History use remaining height

## Core decision

Remove the fixed 28rem minimum from the narrow workbench History section;
retain its flex growth, internal clipping/scroll and the bounded Working Copy.

## Options considered

- Shrink the Working Copy's 38% reservation. Rejected: the bug occurs because
  History refuses to shrink, and reducing Working Copy would take space from
  the place a user stages and commits.
- Allow the whole main workbench to scroll. Rejected: it hides the Working Copy
  below the viewport, precisely the failure the existing E2E test prevents.
- Change breakpoints or hide content. Rejected: the same narrow panel must keep
  both navigation and History usable.

## Final decision and rationale

At 640×900, the original local Chromium feedback loop measured 123px of main
overflow and History only ~477px after collapsing navigation. The 28rem
minimum, 208px nav and 38%-height Working Copy overcommitted the available
main height. With `min-h-0`, History takes the actual remaining space and
receives the height released when navigation collapses. The exact two failing
tests went green without changing their assertions.

## Key changes made

One class in `apps/web/src/routes/+page.svelte`. The original targeted loop
was 2 failed/1 passed; after the change 3/3 passed. The full
`workbench-layout.spec.ts` passed 24/24 across Chromium, Firefox and WebKit.
Web build and `svelte-check` passed with zero errors. Generated Paraglide
metadata changed by the local build was restored; no generated files belong
to this fix.
