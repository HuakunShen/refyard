## Core decision/topic

Repair the Windows test fixtures exposed by CI run `36528190538`; keep the
production ACL contract unchanged.

## Options considered

- Change production directory/file inheritance policy to satisfy the failing
  test. Rejected: the path-aware assertion showed the first failure occurs in
  the `legacy ACL fixture` setup, before the host reopens or runs production
  repair. Windows reads back flags `0` for the fixture's attempt to put OI|CI
  on a file, so that fixture never represents the legacy state it claims to
  seed.
- Relax the directory assertion or accept unknown file owners. Rejected: both
  would weaken real privacy checks to accommodate invalid test setup.
- Reuse valid private files created by `Journal`, remove the initialization
  marker, and mutate those files in place to construct legacy journal contents.
  Chosen: it preserves current-user ownership and ACLs while exercising the
  intended migration and ambiguous-request refusal paths.

## Final decision & rationale

Treat Windows' ACE normalization and owner checks as part of the contract. Drop
the unrepresentable file-inheritance fixture; the same test already verifies
file ACL repair by loosening real private files to a NULL DACL and reopening.
For journal migration tests, use `Journal::open` and `append` to create valid
private files first, then remove the marker and rewrite existing file contents.
The unsafe test assumptions are removed without changing production checks or
expected security flags.
