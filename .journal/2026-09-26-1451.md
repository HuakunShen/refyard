# 2026-09-26 14:51 +08 — Refyard Xross UI review P1 repairs

## Core decision/topic

Repair two consolidated-review P1 findings in the upstream Refyard UI branch, without taking the Rust facade branch or the deferred P2 batch into this commit.

## Options considered

- Leave all mutation preview UI under commit capability and only change button visibility. Rejected: Stage and Unstage could advertise correctly yet still leave their preview inaccessible.
- Have the local Xross build continue through SvelteKit and delete the root route and service worker after emission. Rejected: the ordinary route and session code remained in emitted JS, and runtime request traces could not prove artifact isolation.
- Build a separate Xross-only Vite graph from the existing `/xross` page and facade session. Chosen: the UI stays shared, but the local artifact can exclude SvelteKit's route graph and browser/Tauri transport code at build time.

## Final decision and rationale

Render the native-approval preview independently of commit capability, adjacent to the status actions that produced it. The preview itself names its target resource and operation, and submission still calls only the native approval facade. Build local and hosted Xross packs with a dedicated Svelte entry, no public directory, and a build-time forbidden-module graph gate. Scan every emitted local file and inspect all text assets for forbidden service-worker, manifest, HTTP API and Tauri adapter markers. This makes the artifact boundary checkable without relying on browser navigation alone.
