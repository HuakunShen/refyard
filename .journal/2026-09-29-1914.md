# 2026-09-29 19:14 +08 — Narrow History viewport after the Unix UI gate

## Core decision

The earlier stacked-workbench fix removed History's unconditional 28rem minimum so a 640×900 viewport could keep navigation, History and Working Copy inside the screen. Exact-head CI at `2bb784638cc9e44c328750b94e2ae4285462eaa5` proved that change cleared the six prior layout failures, but its full Ubuntu and macOS E2E jobs both failed the same 390×844 filtered-History case in Chromium, Firefox and WebKit. The History scroll element measured `clientHeight = 0`, so virtualization rendered no commit rows even though `/api/v1/history` returned successfully.

## Options considered

- Restore the unconditional 28rem minimum: rejected because it reinstates the proven 640×900 overflow and hides Working Copy below the viewport.
- Shrink Working Copy's 38% allocation everywhere: rejected because it reduces an independent writing surface to compensate for the reading surface, including at widths where the original layout fits.
- Make the virtualizer render rows with a zero-height viewport: rejected because it would hide a layout failure behind an incorrect measurement and could break bounded rendering.
- Reserve a History height only below a 40rem **container** width and allow the existing outer main scroll there: selected. A narrow workbench cannot fit all three panes and expanded filters at once; natural vertical scrolling preserves an actual History list without regressing the 640px fitted layout. A viewport-media `max-sm` proposal was rejected after adversarial review and a red 1280px-viewport/390px-workbench test: embedded Xross chrome can narrow the workbench independently of the browser viewport. The first container-query shorthand `@max-sm` also failed because Tailwind generated its container cutoff at 24rem (384px), below the 390px fixture; an explicit `@max-[40rem]` compiled to the intended cutoff.

## Key changes and evidence

- `apps/web/src/routes/+page.svelte` adds `@max-[40rem]:min-h-[28rem]` to the stacked History panel.
- `tests/e2e/history-search.spec.ts` asserts a nonzero usable `history-scroll` viewport before checking the virtualized rows. The new assertion was red locally with `Received: 0` before the style change; the same real-Git test passed after rebuilding the web/CLI bundle.
- A separate embedded-column E2E (1280px viewport, 390px workbench) was red with `clientHeight = 0` under `max-sm` and green with the explicit container query. The web production build passed and emitted the expected `@container not (width >= 40rem)` rule. The expanded History and workbench-layout suites passed **33/33** across Chromium, Firefox and WebKit. `svelte-check` reported zero errors and three existing warnings. `git diff --check` passed; the changed test was formatted. The page file's whole-file Prettier check fails on both this tree and the committed baseline, so it is not treated as a new formatting regression.

## Future consideration

This is a Unix UI gate candidate, not an accepted upstream pin or a distributed Xross product. A fresh exact-head CI run must verify Ubuntu and macOS after the commit and push. The Windows full verify job at the previous head independently timed out waiting for the `restart_recovers_without_retry_and_keeps_actor_isolation` hook; the user deferred Windows, so that failure remains separate and unclaimed.
