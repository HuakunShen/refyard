# 2026-09-26 12:22 +08 — Merge Refyard main into Xross facade branch

## Core decision

Keep Refyard's independent application behavior while adapting its new write effects to the Xross facade's asynchronous, root-leased target resolution.

## Options considered

- Leave the Xross branch pinned to the earlier Refyard main. This would keep local tests green but make the integration PR fail when GitHub merges it with current main.
- Narrow standalone `with_writes` to stage, unstage, and commit. This made the newly merged branch/remotes/stash/worktree tests refuse operations and would regress current main.
- Restore the standalone effect set from current main, while keeping embedded callers on `with_embed_options` with an explicit mutation subset.

## Final decision and rationale

Take the third option. Every new write call resolves its target asynchronously, preserving the root lease across execution. Standalone composition retains all effects already offered on main; the Xross embedded facade still allows only its explicitly selected mutation kinds. An independent GPT-6 Sol medium review found no P0/P1 issue in this merge.

## Key changes and evidence

- Added `.await` to 33 `WriteHost::resolve` calls in nine new or changed write modules from main.
- Rebuilt the standalone engine with its full implemented effect set and retained that set for subsequent state-root rebuilding.
- Local release build, full Rust workspace tests (718 passed, 20 ignored, 16 filtered), strict host/core/contract Clippy, and formatting passed on macOS.
- The incoming main contains generated Paraglide JavaScript with pre-existing trailing whitespace; this merge does not rewrite generated output merely to clear `git diff --cached --check`.
