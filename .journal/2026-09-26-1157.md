# 2026-09-26 11:57 — Worktree reads, root revocation, and durable request lookup

## Core decision/topic

Complete Refyard's standalone Rust host facade for multi-worktree inspection and
make workspace-root revocation serialize safely with reads and Git mutations,
while adding durable actor-scoped lookup for accepted client request ids.

## Options considered

- Validate a root only when resolving a request, or hold a root-operation lease
  across the complete filesystem/Git operation. A one-time check leaves a race
  where root removal returns while a previously admitted Git effect is still
  running.
- Report `worktreeListZ` based on version/build assumptions, or run the exact
  porcelain command against a temporary bare repository. Only the latter
  describes the installed Git executable.
- Search a bounded recent operation page for recovery, or index all retained
  actor/request-id keys in the durable journal. A recent-page scan can misreport
  an accepted request as unknown and can permit duplicate effects.

## Final decision & rationale

Use shared root state and a read/write operation barrier. Reads and mutation
effects hold read leases for their full lifetime; removal takes the exclusive
lease, retires the durable root id, and invalidates its resources before it
returns. This makes removal a real drain boundary rather than a check-then-act
best effort. Probe the installed worktree-list feature with Git itself. Serialize
duplicate admission with durable actor/request indexing so process restart,
actor isolation, retention and operation-id monotonicity remain explicit.

## Key changes made

- Added typed Rust contracts and reads for worktrees, stashes and submodules,
  plus durable `WorkspaceRootId` persistence and selected-worktree resolution.
- Projected status, diff and path previews from the requested linked worktree
  rather than silently reading the primary worktree.
- Added capability declarations for the new reads and an exact Git feature

- Added public actor-scoped request-id lookup and atomic journal admission,

- Added root-removal interleaving coverage proving removal waits for an in-flight
  commit; added regression coverage for selected-worktree previews.
