# 2026-09-26 13:31 +08 — Embedded shutdown owns spawned mutation tasks

## Core decision

Make mutation shutdown wait for each spawned ticket task to finish before an embedded host releases its journal lock.

## Options considered

- Keep polling the queue's running count. This observes slot release inside `run_ticket`, before the spawned task drops its final `Arc<MutationEngine>` and its journal.
- Retry opening the journal in the test or add a delay to close. Neither establishes the lifecycle guarantee; both only shift the race.
- Track task handles and join them. This observes the actual owner that can keep the journal locked.

## Final decision and rationale

The engine records join handles as it spawns tickets. Registration and queue closing share one short lock, so a task cannot start outside shutdown's captured set. A second async gate serializes concurrent shutdown callers. Shutdown cancels queued tickets, then joins all captured tasks, even if one queued cancellation fails. A panicked effect still leaves its journal record for recovery; joining does not invent a terminal outcome.

## Key changes

- `crates/refyard-host/src/jobs/mod.rs`: track spawned ticket tasks, close the queue under the same registration lock, and await task completion.
- Existing `close_does_not_fabricate_a_terminal_result` is the regression: macOS CI failed when it reopened the journal immediately after close (run 36219709635, job 108342562570). The same pre-fix test passed locally, confirming the race is schedule dependent.

## Future considerations

No further work is needed for this shutdown race if the focused and full native host suites remain green.
