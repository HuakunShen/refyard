# Timestamp: 2026-09-29 11:43 SGT

## Core decision/topic

Use object-type-specific inheritance flags for Refyard's protected Windows
state ACLs: explicit ACEs on files carry no inheritance flags, while private
directories retain `OBJECT_INHERIT_ACE | CONTAINER_INHERIT_ACE` for descendants.

## Options considered

- Keep the shared OI|CI ACL recipe for files and directories. Rejected: leaf
  files have no children to protect, and the readback oracle compares exact ACE
  flags; the CrossCopy predecessor also uses flags by object type.
- Change construction only and leave the verifier and test oracle unchanged.
  Rejected in GPT-6 Sol High review: that would make the implementation
  self-inconsistent and leave the independent Windows oracle expecting the old
  file policy.
- Change construction, exact readback, and the independent test oracle
  together, and add a legacy-file repair test. Chosen.

## Final decision & rationale

Carry an explicit file/directory kind through ACL construction and readback.
Keep all other authority checks unchanged: current-user ownership, protected
two-ACE DACL, exact user/SYSTEM identities and rights, reparse refusal, and no
ownership change while repairing existing files. A compatibility regression
fixture gives an existing journal record the old OI|CI file ACL, reopens the
embedded host, then verifies the ACL is repaired and the record bytes are
unchanged. This is a source-based policy correction; it does not establish the
root cause of any hosted CI failure.
